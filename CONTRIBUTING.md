# Contributing to Ariesworx projects

Thanks for helping. These are the defaults for every Ariesworx repository; a
repository's own CONTRIBUTING.md adds to or overrides them.

Please read the [Code of Conduct](CODE_OF_CONDUCT.md) first. Security problems
go through [SECURITY.md](SECURITY.md), never a public issue.

## Issues

Search first, then use the issue form. A good bug report says what you did,
what you expected, what happened instead, and the versions involved.

## Pull requests

1. **Open an issue first** for anything larger than a small fix, so we can
   agree on the approach before you spend time on it.
2. **Branch** from the default branch, named with a type prefix and lowercase
   kebab-case:

   | Prefix | For |
   |---|---|
   | `feature/` | new functionality |
   | `fix/` | bug fixes |
   | `maintenance/` | dependencies, tooling, build and config |
   | `docs/` | documentation only |
   | `refactor/` | restructuring with no behavior change |

3. **Title** the pull request with the same type: `fix: hydration warning on the dev server`.
4. **Keep it focused.** One change per pull request; match the surrounding code.
5. **Run the repository's checks** before you push (its README says how) and
   fill in the pull request template.
6. **Sign your commits.** The default branches require signed commits.
